# شبیه‌سازی FDTD — راهنمای اجرا

سه فایل در این پوشه هست و ترتیب استفاده‌شان مهم است:

```
۱)  nanorod_purcell.lsf   →  در Lumerical FDTD اجرا کنید
۲)  make_figures.py       →  روی ویندوز، بعد از اتمام شبیه‌سازی
۳)  (به‌صورت خودکار)       →  اعداد را در فایل‌های .tex جای‌گذاری کنید
```

## گام ۱ — اجرای شبیه‌سازی

پیش از اجرا، فقط بخش «۱) پارامترهای هندسی و طیفی» در ابتدای
`nanorod_purcell.lsf` را ببینید. مقادیر پیش‌فرض:

| پارامتر | مقدار پیش‌فرض | توضیح |
| --- | --- | --- |
| `L_total` | ۶۰ نانومتر | طول کل، **شامل** دو کلاهک نیم‌کروی (بدنه ۴۰ + دو کلاهک ۱۰) |
| `D_rod` | ۲۰ نانومتر | قطر میله؛ `R_cap = D/2` خودکار حساب می‌شود |
| `d_gap` | ۵ نانومتر | فاصله‌ی دوقطبی از راس — این عدد در متن مقاله آمده، تغییرش ندهید |
| `lam_min/max` | ۴۵۰ تا ۸۰۰ نانومتر | بازه‌ی طیفی |
| `mesh_acc` | ۳ | دقت مش سراسری |
| `dx_fine` | ۲ نانومتر | گام مش موضعی روی میله و گپ |
| `mesh_span_xy/z` | ۴۰ / ۸۰ نانومتر | ابعاد ناحیه‌ی Mesh Override |
| `fdtd_span` | ۶۰۰ نانومتر | ضلع مکعب ناحیه‌ی FDTD (با PML) |
| `box_span` | ۴۰۰ نانومتر | ضلع مکعب مانیتور توان `trans_box` |
| `use_gap_mesh` | ۰ | ۱ = یک ناحیه‌ی مش نصف‌گام هم در گپ (فقط آزمون همگرایی) |
| `use_symmetry` | ۰ | ← بخوانید پایین |

این مقادیر **همان اجرای گزارش‌شده در مقاله‌اند**، نه پیش‌فرض دلخواه؛ اگر
عوضشان کنید اعداد بخش ۴ دیگر بازتولید نمی‌شوند. مقدار نهایی `L_total` و
`D_rod` باید در `manuscript/sections/03_methodology.tex` جای $L$ و $D$
بنشیند (اکنون ۶۰ و ۲۰ نانومتر نوشته شده است).

اجرا:

```
File > Run Script...   →  nanorod_purcell.lsf
```

یا از خط فرمان:

```
"C:\Program Files\Lumerical\v###\bin\fdtd-solutions.exe" -run nanorod_purcell.lsf
```

اسکریپت خودش `newproject` می‌زند و همه‌چیز را از صفر می‌سازد، پس نیازی به
فایل `.fsp` آماده نیست.

### `use_symmetry`

دوقطبی در راستای $z$ است، پس شرط مرزی Anti-Symmetric روی `x min` و
`y min` از نظر فیزیکی درست است و زمان اجرا را حدود چهار برابر کم می‌کند.
پیش‌فرض را روی صفر گذاشته‌ام چون اگر بعداً بخواهید جهت دوقطبی را عوض کنید
(مثلاً برای بررسی ادعای وابستگی به جهت‌گیری در زیربخش ۴.۵)، تقارن نتیجه را
بی‌سروصدا غلط می‌کند. برای اجرای سریع‌تر با همین دوقطبی طولی،
`use_symmetry = 1;` بگذارید.

### کنترل کیفیت خودکار

اسکریپت موازنه‌ی انرژی $F_p \approx T + A_{\text{metal}}$ را با یک
مانیتور جذب مستقل (`abs_box`) می‌سنجد و درصد خطا را چاپ می‌کند. اگر بیش از
۵٪ بود هشدار می‌دهد؛ در آن صورت `mesh_acc` را بالا ببرید یا `dx_fine` را
ریزتر کنید. این عدد در `peaks.csv` هم ذخیره می‌شود.

### خروجی‌ها

| فایل | محتوا |
| --- | --- |
| `spectra.csv` | `lambda_nm, Fp, T, eta_a, A_metal` |
| `peaks.csv` | مقادیر قله‌ها + پارامترهای هندسی + خطای موازنه |
| `nearfield.csv` | ماتریس $\vert E\vert^2$ در صفحه‌ی $y=0$ |
| `nearfield_axes.csv` | محورهای x و z بر حسب نانومتر |
| `nanorod_purcell.fsp` | پروژه‌ی ذخیره‌شده |

## گام ۲ — ساخت شکل‌ها

```
python simulation\make_figures.py
```

نیازمندی: `numpy` و `matplotlib` (روی این سیستم موجودند: numpy 2.4.4،
matplotlib 3.10.9).

سه شکل با همان نام‌هایی که `04_results.tex` انتظار دارد در
`manuscript/figures/` ساخته می‌شود:

- `Purcell_Spectrum.pdf`
- `radiated_power_T.pdf` — دو قله و فاصله‌ی $\Delta\lambda$ روی نمودار
  علامت‌گذاری می‌شود، و $\eta_a$ روی محور راست می‌آید
- `NearField_Profile.png` — مقیاس رنگ لگاریتمی، به‌همراه طرح‌واره‌ی میله و
  نشانگر مکان دوقطبی

برچسب‌های شکل‌ها انگلیسی است. متن فارسی داخل matplotlib به
`arabic_reshaper` و `python-bidi` نیاز دارد و ارزش افزودن دو وابستگی را
ندارد؛ در مقاله‌های فارسی هم برچسب انگلیسی روی شکل رواج دارد.

## گام ۳ — به‌روزرسانی متن

`make_figures.py` فایل `simulation/_numbers_for_text.txt` را می‌سازد که
همه‌ی عددها را با همان قالبی که در متن آمده‌اند فهرست می‌کند.

> **مهم:** فایل‌های `.tex` در حال حاضر عددهای اجرای قبلی را دارند:
> $F_p = 2020.48$ در $607.9$ نانومتر، $T = 143.42$ در $615.1$ نانومتر،
> $\eta_a = 7.1\%$، و $F_p - T = 1877.06$. اگر اجرای شما عدد دیگری داد،
> باید در **سه** جا اصلاح شود: `main.tex` (چکیده)،
> `04_results.tex` (زیربخش‌های ۴.۱ تا ۴.۳ و ۴.۵)، و `05_conclusion.tex`.
> فایل `_numbers_for_text.txt` همین هشدار را با عددهای واقعی تکرار می‌کند.

سپس در `manuscript/sections/04_results.tex` سه سطر `\includegraphics`
از قبل فعال است، پس تنها اگر نام فایل‌ها را عوض کردید دست بزنید. برای
به‌روزکردن نسخه‌ی PNG که پیش‌نمایش HTML استفاده می‌کند:

```
python tools\figures_prep.py
```

و در پایان، پیش‌نمایش و بسته‌ی تحویلی را از نو بسازید (ساخت PDF فعلاً
مسدود است — به `manuscript/README.md` نگاه کنید):

```
python tools\make_review_zip.py
```
